此次比賽進球流量及速度皆超過人類手動計算極限
方案選擇:HSV + AI 混合 — 取兩者長處，系統較複雜，但最平衡。採用。
球偵測用 HSV（黃色球顏色鮮豔，過濾就夠）、機器人偵測用YOLO偵測bumper為主，HSV備選、GUI 用 CustomTkinter（Python 生態、暗色看起來舒服）。


系統架構

使用者介面（主視窗 + 設定面板）
　　↓
分析管線（逐幀處理）
　├─ 球偵測（HSV 色彩過濾 / AI 備用）→ 球追蹤（質心匹配）
　├─ 機器人偵測（YOLO /HSV Bumper ）→ 機器人追蹤（距離匹配 + Re-ID）
　├─ 背景模型（自動前景分離）
　└─ 進球判定 + 射手歸因 + 出手偵測
　　↓
輸出：得分統計表 / 進球事件時間軸 / CSV 匯出

每一幀的處理流程：
讀取影片幀 → 裁切分析區域 → 背景遮罩（觀眾席變黑）→ 球偵測（找黃色物體）→ 球追蹤（連接同一顆球）→ 機器人偵測（找紅藍 Bumper）→ 機器人追蹤（辨識是哪台）→ 進球判定 → 記錄事件










球偵測:
HSV 色彩過濾（採用方案）
FRC 的球是亮黃色的，在 HSV 色彩空間裡很容易跟背景分開。

處理流程：原始影像 → 高斯模糊（消除運動模糊）→ 轉 HSV → 黃色範圍過濾 → Close 形態學 7x7（把碎裂的球補成整塊）→ Open 形態學 3x3（去小噪點）→ 找輪廓 → 面積過濾 → 輸出球位置

中間遇到的問題：形態學順序寫反了（先 Open 再 Close），球偵測直接壞掉。原因是球的色彩 mask 本身有洞，先 Open 會把碎片全刪掉，Close 也救不回來。改成先 Close 再 Open 之後恢復正常

AI 模式（放棄）

也試過 YOLO 做球偵測，近距離效果不錯（信心值 0.67），但遠距離完全不行。原因：訓練資料是近距離球特寫，比賽影片是廣角遠景，球只有十幾像素。後來決定球偵測就用 HSV，黃色球在任何距離都是黃色的

HSV 自動校正

每個場地燈光不同，HSV 參數也要跟著調。解決方案:自動校正：用戶在影片上點幾下球的位置，系統用 K-Means 分離球色 vs 背景，再用百分位法自動算出 HSV 範圍。比手動調 slider 快很多。













機器人偵測

第一版：YOLO 偵測

用 Roboflow 的 Main Robot Detection 資料集（1,172 張，Red / Blue 兩類），在 Google Colab 免費 T4 GPU 上訓練 YOLOv11n，約 30 分鐘練完，匯出 ONNX（10.1 MB）。

中間遇到的問題:
一開始選了 WorBots 4145 資料集（3,291 張），但類別超雜，模型把記分板、音箱都框成「機器人」。改成只有 Red/Blue 兩類的資料集後解決

第二版：HSV Bumper 偵測

Bumper（防撞條）每年都有，而且一定是紅色或藍色（FRC 規則規定）。所以做了 HSV 偵測器找紅藍矩形色塊。

處理流程：模糊 + HSV 轉換 → 紅色過濾（兩段範圍，處理 Hue 環繞）→ 藍色過濾 → 合併 → 矩形核形態學（Bumper 是扁的）→ 輪廓偵測 → 面積 + 長寬比過濾 → NMS 去重 → 模板匹配過濾（可選）

設計細節：紅色在 HSV 裡 Hue 值跨越 0 度（會環繞），必須做兩次過濾再合併。形態學用矩形核（9x5）而非正方形，因為 Bumper 是水平長條形。

Bumper 模板匹配：用戶可以在影片上點幾下機器人的 Bumper，系統建立 HSV 直方圖模板，分析時只保留跟模板相似的偵測結果，過濾掉觀眾衣服、標示牌等假陽性。























多目標追蹤（MOT）

問題:ByteTrack 用 IoU（框的重疊面積）來配對前後幀的偵測結果，一般場景很好用，但這裡完全失效

原因：4K 影片裡機器人的框只有約 25 像素，但每幀移動 30~50 像素。框的位移比框本身還大，前後幀完全不重疊，IoU 永遠是 0，配對全失敗。1200 幀裡只成功配對 11 次（覆蓋率 5.4%）。

解法：距離匹配

改用距離來配對。同一台機器人在連續幀之間位置不會差太遠。

匹配流程：
1. 每台已追蹤的機器人，用速度預測下一幀位置
2. 計算所有「預測位置 ↔ 偵測結果」的距離
3. 加入顏色直方圖 Re-ID：外觀不像的候選距離會被拉遠
4. 全域最短距離優先，貪心配對
5. 距離超過閾值的不配對（視為新目標）

修復前後對比：
機器人偵測次數：ByteTrack 11 次 → 距離匹配 1,000 次
插值後涵蓋幀數：11 → 4,521
幀覆蓋率：5.4% → 100%
Blue 機器人追蹤：0 台 → 5 台























背景模型

比賽影片裡觀眾席、計分板的顏色會干擾偵測。一開始用手動畫多邊形遮罩，但每換影片都要重畫，很麻煩。

Temporal Median 自動背景

原理：場地和觀眾席是不動的，機器人和球是快速移動的。

1. 從影片均勻取 50 幀
2. 每個像素位置取中位數 → 得到一張「乾淨的背景圖」
3. 分析時：每幀減去背景圖，差異大的地方 = 前景（機器人和球）
4. 背景區域設為黑色，偵測器只看前景

中位數對離群值穩健。如果某幾幀剛好有機器人停在某處，平均數會被拉偏，中位數不會。效果比手動畫遮罩好太多

射手歸因率極低
不同場地的參數差異大，自動適配還沒做好
